Packiko Video SDK — vanilla walkthrough

ทีละขั้นด้วย JavaScript ล้วน ไม่ต้องมี bundler/React — เปิดกล่องไล่จากบนลงล่าง แล้วดูผลจริงใน Event log ล่างสุด

⚠ ก่อนเริ่ม — 3 อย่างที่ต้องมี ไม่งั้นจะติดตั้งแต่ขั้นอัปโหลด
  • Origin ต้องขึ้นทะเบียน: key pk_... ทุกตัวถูกผูกกับโดเมนที่แจ้งไว้เท่านั้น — key ของคุณใช้ได้จากโดเมนของคุณ (เช่น localhost ตอน dev) เอามากรอกบนหน้านี้จะเจอ "โดเมนนี้ยังไม่ได้ขึ้นทะเบียน" ซึ่งถูกต้องแล้ว · แจ้ง origin ที่จะใช้กับ ThaiCloud ก่อนเริ่ม
  • Publishable key (pk_...) จาก tenant ของคุณ — ปลอดภัยในเบราว์เซอร์ ไม่มี secret
  • สิทธิ์กล้อง+ไมค์ — เบราว์เซอร์จะถามตอนเปิดขั้น 2
อยากลองครบวงจรบนหน้านี้เลย: เลือก Mode B ในขั้น 1 (key demo เตรียมไว้ให้แล้ว) หรือขอ key ที่ขึ้นทะเบียนกับ example.packiko.com
ขั้น 1 · เลือกโหมด auth + ตั้งค่า SDK ยังไม่เลือกโหมด

❓ คำถามเดียวตัดสินทุกอย่างที่เหลือ: ระบบ login ของคุณใช้ IdP แบบ OIDC ที่เผยแพร่ JWKS ไหม (Keycloak, Auth0, Entra ID — มี .well-known/openid-configuration)?

Mode A — ใช้แค่ publishable key (pk_...) ปลอดภัยในเบราว์เซอร์ ไม่มี secret · "วิดีโอเป็นของ user ไหน" คุณรับรองเองผ่าน externalUserRef (server ไม่ verify) · ระบบ token แบบ HS256 (symmetric) server verify ข้ามองค์กรไม่ได้ จึงอยู่กลุ่มนี้

<script src="https://sdk-uat.packiko.com/video/v0.3.0/index.global.js"></script>
const { createRecorder, createPlaybackResolver, createUploadQueue } = PackikoVideo;
const config = { apiBaseUrl, publicKey };
ส่งเป็น externalUserRef ตอนอัปโหลด — คลิปบันทึกว่าใครเป็นคนอัด

Mode B — user login กับ IdP ของคุณ → SDK แนบ JWT เป็น X-User-Token ให้ทุก request → server verify ลายเซ็น/issuer/วันหมดอายุผ่าน JWKS ของคุณ → วิดีโอผูกกับ sub ที่ verify แล้ว — ต่อให้ pk_ หลุด คนอื่นก็ mint ไม่ได้เพราะไม่มี token จริง · enforce-or-reject: token หาย/หมดอายุ = 401 เสมอ ไม่หล่นกลับ Mode A เงียบๆ

// vanilla: เพิ่ม getUserToken ใน config — ที่เหลือ SDK จัดการเอง
import Keycloak from 'https://cdn.jsdelivr.net/npm/keycloak-js@26/+esm';
const kc = new Keycloak({ url, realm, clientId });
await kc.init({ pkceMethod: 'S256' });            // login เป็น redirect ไป-กลับ
const config = { apiBaseUrl, publicKey,            // pk ตัวที่เปิด Mode B ไว้
  getUserToken: async () => { await kc.updateToken(30); return kc.token; } };

ค่า default = demo tenant ของ ThaiCloud (UAT) — ชี้ IdP ของคุณเองได้โดยแก้ 4 ช่องนี้

สถานะ: กำลังเตรียม…

API base URL ใช้ร่วมทั้งสองโหมด · ขั้น 2-4 ข้างล่างใช้ config จากขั้นนี้อัตโนมัติ
ขั้น 2 · อัดวิดีโอ + อัปโหลด ยังไม่เปิดกล้อง

กล้องเปิดตอนกางกล่องนี้ (หุบกล่อง = ปิดกล้อง) · กด "หยุดอัด" ได้เสมอ — ไฟล์จะรอในหน้า แล้วค่อยกดอัปโหลดเมื่อพร้อม

const cap = await createRecorder(config).capture();   // ขอกล้อง + preview
cap.start();                                           // เริ่มอัด
const blob = await cap.stop();                         // ได้ไฟล์ (หยุดได้เสมอ ไม่ต้องมี key)
const up = createRecorder(config).upload(blob, { orderRef, externalUserRef });
const { videoId } = await up.promise;                  // สำเร็จ = ได้ videoId
capture: ยังไม่เปิดกล้อง
🎬 คลิปพร้อมแล้ว ()

🎉 videoId: — ใส่ให้ในขั้น 3 แล้ว

ขั้น 3 · เปิดดูวิดีโอ รอ videoId

เอา videoId ไปขอลิงก์เล่น — คลิปที่พร้อมแล้วได้ลิงก์ทันที · คลิปที่เพิ่งอัดอาจยังประมวลผลอยู่ กด "ลองใหม่" ได้เรื่อยๆ ไม่ใช่ความผิดพลาด

const resolver = createPlaybackResolver(config);
const res = await resolver.resolve(videoId);
// res.status: "ready" (ได้ res.url) | "processing" (รอแป๊บแล้วลองใหม่) | "unavailable"

สถานะ: idle

ขั้น 4 · คิวถาวร + ผูกเอกสารทีหลัง —

โจทย์จริงหน้างาน: พนักงานอัดคลิปแพ็คของเสร็จ แต่ออเดอร์ในระบบยังบันทึกไม่เสร็จ — คลิปยังไม่มีที่ให้ผูก แถมเน็ตหน้าคลังก็ไม่นิ่ง ถ้าอัปโหลดตรงๆ แบบขั้น 2 คลิปหายกลางทางได้

คิวถาวรรับปาก 3 อย่าง:

  • 📦 รับไฟล์ปุ๊บ เก็บลงเครื่องทันที — ยังไม่ยิงเน็ตสักไบต์ · ปิดแท็บ/refresh/เน็ตหลุด คลิปไม่หาย
  • ⬆ อัปโหลดเบื้องหลัง + ลองซ้ำให้เอง — ไฟล์ที่ขึ้นแล้วไม่อัปซ้ำ
  • 🔗 รอจนเอกสารของระบบคุณพร้อม แล้วค่อยผูกให้ — ระหว่างรอไม่นับเป็น fail แค่ "จอดรอ"
const queue = createUploadQueue(config, {
  releaseWhen: (job) => documentReady(job.context),    // false = จอดรอ ไม่ใช่ fail
  attach: (job) => bindClip(job.context, job.videoId), // ต้อง idempotent
});
await queue.enqueue({ blob, context, orderRef });      // durable ทันที
await queue.nudge();                                   // เอกสารพร้อมแล้ว เช็คเดี๋ยวนี้

ลองตามนี้ (demo จำลอง "เอกสาร" ไว้ในหน้าเว็บ — ของจริงคือระบบหลังบ้านของคุณ):

  1. กด "ใช้คลิปจากขั้น 2" หรือเลือกไฟล์วิดีโออะไรก็ได้ในเครื่อง (ของจริงโค้ดคุณส่ง blob จากตัวอัดเข้าคิวตรงๆ ไม่มีการเลือกไฟล์) → ดูสถานะวิ่ง queued → uploading → uploaded แล้วจอดรอ เพราะยังไม่มีเอกสาร
  2. ใจกล้าๆ refresh หน้าตรงนี้เลย — job กลับมารอที่เดิม คลิปไม่หาย
  3. กด "สร้างเอกสาร (nudge)" = แกล้งเป็นระบบคุณบันทึกออเดอร์เสร็จ → คิวผูกคลิปทันที แล้วลบไฟล์ในเครื่อง 🎉
